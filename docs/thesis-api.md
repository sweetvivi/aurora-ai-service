# 论文写作接口

> 模块：`com.hub.backend.modules.thesis`　表：`thesis_documents`（`V55__thesis_documents.sql` + `V56__thesis_workbench_dimensions.sql`）
> 前端：`frontend/src/views/thesis/`（挂在站点导航「近期热门 → 论文助手」，路由 `/thesis`）
> 基础路径：`/api/v1/thesis`　鉴权：除「表单选项 / 题目优化 / 生成大纲」外均需 `Authorization: Bearer <accessToken>`

## 1. 为什么要独立成一个模块

前端工具台的第一步（填写学历、学科、题目 → 生成三级大纲）不需要模型调用：骨架是稳定的，
第三章才按学历层次分叉。把这一步做成**确定性的模板引擎**而不是模型调用，有三个直接好处：

1. 「免费生成大纲」真的免费且瞬时，不会被上游限流影响，也不会因为模型波动给出坏结构；
2. 同一组入参永远得到同一棵树，编辑器的改名/增删操作可以做 diff，验收可复现；
3. 第三步接模型时只替换 `ThesisOutlineGenerator`，Controller 与前端契约不动。

## 2. 两套生成引擎

`POST /outlines` 有两条路径，由请求体 `useModel` 决定：

| 引擎 | `useModel` | 成本 | 说明 |
|---|---|---|---|
| 模板 | `false`（缺省） | 0 token，毫秒级 | 确定性模板引擎，可无限重试 |
| 模型 | `true` | 按 token 计费 | 调用上游语言模型生成标题层级 |

**模型模式的三条约束**（都是刻意的）：

1. **只生成标题，不生成正文。** 正文属于抽屉里的「生成全文」，按 token 计费（与大纲、对话共用同一份 New API 余额）；让免费步骤顺带写正文，
   会让一个宣称免费的按钮偷偷消耗 token。
2. **输出是解析出来的，不是信任的。** 模型可能返回 markdown、JSON、缩进列表或一句客套话；
   `ThesisModelOutlineGenerator.parseOutline` 接受前三种，第四种返回空列表。
3. **任何失败都回落模板。** 上游超时、key 失效、返回不可解析 —— 一律 `200 + mode=TEMPLATE`，
   不让免费功能变成错误页。响应里的 `mode` 会告诉客户端实际用了哪个。

响应结构：

```json
{
  "outline": [ { "id": "n_1", "title": "第一章 绪论", "level": 1, "children": [] } ],
  "mode": "MODEL",
  "model": "deepseek-v4.1-flash"
}
```

`GET /catalog` 同时给出 `modelEnabled`（服务端是否真的配了可用上游）与 `models`（可选的对话模型），
前端据此启用或置灰「AI 模型」开关，不再对用户许诺做不到的事。

### 本地如何验证真实调用

没有真实 key 也能验证整条链路：

```bash

```

即证明 HTTP 调用、JSON 解析、标题回填都是真的。接真实供应商时只换三个环境变量：


由网关 `/v1/models` 实际返回（当前 4 个 `deepseek-v4*`）。本地 key 存在
`backend/.env.local`（`.gitignore` 已忽略），`bash backend/run-local.sh` 启动时自动注入。

## 2.1 全文生成

`POST /full-text/stream`（SSE）

大纲只给标题，全文才写正文。这一步与大纲的区别是**没有模板回落**：模板引擎能排标题但写不了 8000 字，所以模型不可用时直接 400 说明原因。

### 计费口径：New API 统一计费

**本模块没有自己的价格表、积分或订单。** 全文、大纲、对话、图片共用同一套计费：
New API 是唯一权威，按实际 token 从**调用者自己的中继令牌**所属账户扣减。

| 环节 | 凭据 | 说明 |
|---|---|---|
| 大纲（模型模式） | 当前用户中继令牌 | 拿不到就回落模板，不计费 |
| 全文（含附录、压缩改写） | 当前用户中继令牌 | 每章一次调用，全部记在同一次生成里 |
| 参考文献检索 | 无 | OpenAlex 公开索引，不产生 token |

`checkFullTextBilling` 在**开流之前**执行一次，因此失败是普通 HTTP 状态码而不是
「进度弹窗跑到第一章才报错」：

| 状态码 | 条件 | 客户端应做的事 |
|---|---|---|
| `401` | 未登录（按账号计费时游客没有可扣费账户） | 跳登录，`redirect=/thesis` |
| `402` | New API 账户可用余额 `<= 0` | 引导去 `/user-center/balance` 充值 |
| `503` | 中继令牌开通中 / 计费网关超时 / 未配置静态 key（本地开发） | 稍后重试或检查部署配置 |

余额判断与其它模块同一处实现（`UserGatewayTokenService.requireRelayCredential`），
沿用其 `usage-cache-ttl` 快照节流：只信「够用」，余额为 0 的快照一定回查 New API，
所以充值后立即可用。中继令牌为 `unlimitedQuota` 时 `total_available` 恒为 0，
不能据此判定没钱 —— 前后端都显式排除这种情况。

前端不再展示「¥xx / 篇」这类本地定价，只展示当前余额；余额为 0 时按钮变成「去充值」。
中止生成（关弹窗）会 abort 请求，已产生的 token 照常结算。

### 一章一次调用

`ThesisFullTextGenerator` 按大纲的一级标题顺序逐章调用模型：

| 决策 | 原因 |
|---|---|
| 按章拆分，串行执行 | 一次写完 8000 字要么被 `finish_reason=length` 截断，要么写到第五章就跑题；按章拆能显示进度，一章失败也只重试一章 |
| 每章都重述整份表单 | 独立生成的一章无法推断「这是本科系统类论文、有数据模型」，所以题目 / 学历 / 类型 / 专业 / 层级 / 字数 / 三个开关每次全部带上 |
| 前文摘要传递 | 每章带上前几章的 140 字摘要，避免重复论证并保证衔接 |
| 参考文献与致谢不交给模型 | 让模型「写参考文献」正是伪造引用的来源。这两节由服务端从核验清单组装 |

### 字数控制（目标值 ~ +10%）

用户填的「目标字数」是**上限口径**，交付必须落在 `目标 ~ 目标 × 110%`。三道闸门，从便宜到贵：

| 闸门 | 做法 | 成本 |
|---|---|---|
| ① 分章配额 | 每章下发 `[剩余预算 ÷ 剩余章数] ± 8%` 的闭区间，写超了后面自动收窄；最后一章不因前文写少而膨胀，上限 1.5 倍均值 | 0（只是提示词） |
| ② 超长改写 | 全文超目标 4% 时，从最长的一章开始，按其超出量要求模型压到指定字数（保留全部小节） | 每章一次调用 |
| ③ 句子截断 | ② 没收敛（上游失败 / 不配合）时，从最长章末尾按「。」「！」「？」整句删除，直到落回 110% | 0（纯文本处理） |

②之所以以 4% 而不是 110% 为触发线：压一次要花一章的 token，4% 以内属于可接受范围，不值得为此重写。
③ 只会在模型不配合时出现，每章最低留 400 字；若压到下限仍超限，服务端**如实报告**并在日志里记 `ERROR`，
不会为了凑数把正文删成半句。

字数口径也统一了：`wordCount` = 正文各章之和，**不含**附录、参考文献、致谢。这三个部分此前被算进去，
8000 字的目标会凭空多出五六百字，是「生成完就超」的主要来源之一。

### 参考文献怎么来（关于知网）

**没有抓知网，也不该抓。** 实测 `search.cnki.com.cn` 对自动化访问返回 `HTTP 418`，并弹出验证码墙；绕过它属于规避访问控制，本项目不做。

实际做法：用 **OpenAlex 开放学术索引**（可 API 查询的公开学术库）检索中文文献，并且**只保留带 DOI 的条目**——DOI 是读者能点开核验的那一个字段。代价要说清楚：

| 实测项 | 数据 |
|---|---|
| OpenAlex 中文文献的 DOI 覆盖率 | 约 20–45%（情感分析 4/20、金融舆情 9/20） |
| 检索策略 | 逐主题词查询再合并（整句查询会把无关论文排上来） |
| 相关性过滤 | 标题必须覆盖「主题词」或「主题词 + 领域词」组合；词表外的泛化词不计分 |
| 单次生成通常得到 | 3–10 篇（选题冷门时更少） |

结论：**这批文献是真实的、可核验的，但覆盖不了中文期刊的全部**。要凑齐一篇本科论文的 15–20 篇参考文献，仍需学校图书馆的知网 / 万方入口补充。这一点在界面和 `referenceSource` 字段里都如实写明，不写成「知网文献」。

### 实测

下面这组是**引入字数配额之前**的实测，留着作为「为什么会超」的证据（目标 8000 档却写到 1.25 万字）：

| 指标 | 改动前 |
|---|---|
| 6 章全文耗时 | 88–95 秒 |
| 正文字数 | 11,475–12,512 字（超出目标 43–56%） |
| token 消耗 | 约 1.6k–3.4k / 章，合计约 12k |
| 参考文献 | 10 篇，全部带 DOI |
| 正文引用标记 | 29 处，点击可跳到文末条目 |

改成配额 + 压缩后需要重新跑一轮真实调用才能给出新数字；单元测试只固定配额分配与截断规则，
不覆盖模型的服从度。触发压缩时，预计多出 1–2 次单章调用（每章约 1.6k–3.4k token）。

## 2.2 三个增值项（`referenceEnabled` / `attachmentsEnabled` / `dataModelEnabled`）左侧「增值保障」的三个开关是**对交付内容的具体承诺**，不是装饰性选项。它们与「学历层次」「文本类型」
这两个维度正交：类型决定「这是什么文档」，增值项决定「这份文档额外多带什么」。

| 开关 | 大纲阶段 | 全文阶段 |
|---|---|---|
| `referenceEnabled` | — | 先检索 OpenAlex 带 DOI 的中文文献作为**唯一可引用清单**注入提示词 |
| `attachmentsEnabled` | — | 提示词声明用户会提供参考资料，需呼应（正文与 `material` 一起传） |
| `dataModelEnabled` | 在「参考文献」前追加一级标题 `附录 A 数据模型与关键代码`（含 A.1 数据模型设计 / A.2 关键代码实现，三级再展开） | 正文解除「禁止代码块」，附录单独一次模型调用写出表结构、关键代码与运行说明 |

**为什么用附录而不是插入一章**：13 种文本类型的章数各不相同（5～6 章，末章都是结论），
插一章要么撞号、要么逼着每份骨架重新编号。附录自带 A.x 编号，也正是真实论文放表结构与代码清单的位置。

**为什么两套引擎都要处理这个开关**：模板引擎走 `ThesisOutlineGenerator.appendDataAppendix`，
模型引擎把要求写进 `userPrompt` 的第 6 条 —— 之前只有模板引擎的学历默认骨架里嵌了一个 `3.3.3`，
其余 12 种自带骨架的类型勾选后毫无变化，模型模式更是完全没收到这个参数。

**字数口径**：附录不计入 `wordCount`。附录装的是 DDL 与代码，算进正文字数会让目标字数看起来注水，
而学生核对工作量时比的是正文。

**代码块的渲染约定**：附录里的 SQL / 程序代码必须用 ```` ```lang ```` 围栏返回，服务端
`normaliseBody` 只清理围栏**外**的 `#` 标题行（Python 注释也是 `#`，误删会毁掉整段代码）。
阅读器把它渲染成等宽 `<pre>`，Word 导出转成 `white-space: pre-wrap` 的代码块。

## 2.3 全文落库与「我的稿件」

生成全文时如果请求里带了 `documentId`，服务端在返回前把整份结果写回稿件（`V65__thesis_full_text.sql`）：

| 列 | 用途 |
|---|---|
| `full_text_json` | 原始响应（章节 + 参考文献 + 字数），与 `outline_json` 同样的取舍：整体读写、没有按章查询 |
| `full_text_model` | 生成用的模型，重新打开时如实显示 |
| `full_text_word_count` | 列表页不解析 JSON 就能显示字数 |
| `full_text_generated_at` | 生成时间；早于 `updatedAt` 说明大纲在那之后又改过，列表会提示「正文早于当前大纲」 |

写入失败（唯一约束冲突、JSON 序列化异常）不会让生成变成错误页 —— 正文已经产出了，
只记 `WARN`，用户仍能当场阅读和导出，只是下次不能从列表重新打开。

「我的稿件」（`GET /documents`）因此能给出两个动作：

- **打开大纲**：把表单 + 大纲 + `documentId` 一起载回工作台，继续编辑或重新生成；
- **查看全文**：`GET /documents/{id}/full-text` 取回已保存的正文，直接重新打开阅读器。

没有全文的稿件调用后者返回 `404`（文案：该稿件还没有生成全文），前端退回到「打开大纲」。

## 3. 工作台的两个维度
参考站（ai1foo `/newAiThesis/index`）的工作台把「学历」和「大纲结构」拆成两个独立维度，
本站照此实现，并保留旧字段兼容：

| 维度 | 字段 | 取值 | 作用 |
|---|---|---|---|
| 学历层次 | `educationLevel` | 专科在读 / 专科毕业 / 本科在读 / 本科毕业 / 硕士在读 / 硕士毕业 / 博士在读 / 博士毕业 | 决定大纲模板与默认字数 |
| 大纲结构 | `outlineDepth` | `2` 二级 / `3` 三级 | 决定是否展开到第三层 |
| 文本类型 | `paperType` | 论文助手 / 开题报告 / 期刊文章 …（13 种） | 只影响措辞与导出命名 |

`educationLevel` → `tier` 的映射由服务端完成（`专科/本科 → UNDERGRAD`、`硕士 → MASTER`、
`博士 → DOCTOR`），前端不需要知道内部标识。旧客户端的 `tier` 字段仍在，仅在**没有**
`educationLevel` 时被读取，属于兼容路径。

## 4. 接口清单

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/catalog` | 否 | 学历 8 档、大纲结构、13 种文本类型、学科二级联动、8 档字数 |
| POST | `/outlines/optimize` | 否 | AI 优化题目，返回改写结果 + 一句说明 |
| POST | `/outlines` | 否 | 生成三级大纲，**不落库** |
| POST | `/documents` | 是 | 生成并保存为稿件（状态 `OUTLINE`） |
| GET | `/documents` | 是 | 我的稿件分页（`keyword` / `page` / `size`） |
| GET | `/documents/{id}` | 是 | 稿件详情（含大纲树） |
| GET | `/documents/{id}/full-text` | 是 | 读取已保存的全文；还没有全文时 `404` |
| PUT | `/documents/{id}/outline` | 是 | 整树覆盖保存，版本号 +1 |
| DELETE | `/documents/{id}` | 是 | 软删除 |

## 5. 大纲树结构

```json
{
  "id": "n_lx2k9a_1",
  "title": "1.1 研究背景与意义",
  "level": 2,
  "children": [ { "id": "n_lx2k9a_2", "title": "1.1.1 现实背景", "level": 3, "children": [] } ]
}
```

- 顶层即「章」，`level` 由服务端按位置重算，前端传错不会报错而是被纠正；
- `id` 缺省或重复时服务端补一个新的，前端只在编辑态用它做 key；
- 标题会去首尾空白、折叠连续空白，最长 120 字；空白标题返回 `400`；
- 单次最多 400 个节点，最多三级。

## 6. 保存是「整树覆盖」

改标题、加小节、删节点都由前端先改好整棵树再提交，服务端只做规范化后整体落库：

- 一次保存 = 一次 UPDATE，天然原子，不会出现「删了一半」的中间态；
- 因此不需要 `POST /nodes`、`DELETE /nodes/{id}` 这类细粒度接口，前端也不用处理并发冲突；
- `outlineVersion` 每次加一，前端可比对「我读到的是第几版」来提示「别处已保存」。

## 7. 错误码

| 状态码 | 含义 |
|---|---|
| `400` | 参数校验失败（`details` 为字段级原因）；`outlineDepth` 不是 2/3；节点标题为空 / 层级过深 / 节点超限 |
| `401` | 未登录或令牌失效（走统一鉴权，不回退到演示账号）；全文计费链路下游客也会拿到 `401` |
| `402` | New API 账户可用余额为零，开流前拒绝（见 2.1「计费口径」） |
| `404` | 稿件不存在，或不属于当前账号 |
| `413` | 请求体超限 |
| `429` | 触发限流 |
| `503` | 中继令牌开通中 / 计费网关不可用 / 本地开发未配置静态 key |

约定与其它模块一致：**没有 `code` 信封**，HTTP 2xx 即成功，失败看 `ApiError`。

## 8. 前端对接顺序

```
GET  /catalog                     → 渲染学历 8 格 / 大纲 2 格 / 13 种类型 / 字数 8 格
POST /outlines/optimize           → 「AI 优化题目」
POST /outlines                    → 「立即生成大纲」（不进数据库，可反复点）
PUT  .../outline                  → 树里改名、加小节、删节点后保存
```

前端把这几步和「导出 Word」「生成全文」串成一条流程；全文也在本模块
（`POST /full-text/stream`），计费走 New API 统一口径，没有独立的积分或订单链路。
